# P0 ticket queue candidate
Migration 0012 is additive, no historical backfill. Machine endpoint POST /api/bot/ticket-queue accepts lease/renew/retry/ack with a distinct NEXORAID_TICKET_MACHINE_KEY (64 hex characters), not the actor key. Leases last 180 seconds; the consumer must renew before expiry, and renewal is fenced by the current unexpired token and active order state. Retries use bounded exponential backoff; acknowledgements preserve canonical ticket links and message IDs. Bot consumer integration, crash recovery, membership gating, portal sync display and live E2E remain open. Do not activate or declare stable before these gates. Replaces the conflicting 0007 migration design in old PR #2; do not merge that old migration.

Canonical link writes are machine-lease ACK only. Actor POST is rejected even for the customer. ACK replay requires the same channel, message and ticket ID and canonical customer mapping; cross-customer channel/ticket reuse and split active customer mappings are rejected. Historical conflicts are not automatically rewritten. Live staging and terminal-order closure remain separate gates.

Machine action `closure-status` returns read-only counts for an exact guild/customer/channel/ticket mapping, including every active order for the customer (even unlinked), uncertain delivery and conflicting mappings. A positive snapshot is not authority to close. A durable checkout/closure fence, transcript delivery and idempotent acknowledgement remain mandatory before mutations.

Machine action `readiness` provides only aggregate counts (active orders, historical unqueued, pending, eligible, leased, delivered, inconsistent and split active mappings), even during maintenance. No lease, customer IDs, backfill or mutations. Historical unqueued records require owner reconciliation; counts alone do not authorize Discord delivery or closure.
