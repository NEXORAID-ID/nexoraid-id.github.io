# A19: atomic catalog price snapshot (candidate)
Both order creation routes guard the observed catalog override and scheduled `service_policies` promotion state inside the order INSERT. A mismatch aborts the D1 batch through the existing NOT NULL constraint on `catalog_price`; the API responds 409, with no partial cart/order/audit/outbox. The guard relies on schema 17 from PR #10; A19 adds no migration or production change. Replay remains ahead of catalog validation, preserving original orders. Static prices are tied to the running Worker bundle. Tests exercise SQLite transactions; CI and isolated D1/real client staging are required before declaring A19 verified. The guard compares the server-read catalog against the write; it does not by itself confirm a stale price displayed on a customer's earlier screen.
