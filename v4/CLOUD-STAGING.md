# Dedicated cloud staging (A82)

This smoke environment is intentionally read-only, separate Cloudflare account, Worker and empty D1; no production customer data, tokens, payment or Discord side effects. The local CI still exercises synthetic role and financial flows. A real Discord staging application, test guild, and synthetic accounts/bridge credentials are separate acceptance requirements; never point staging at the production guild (current Worker membership is production-bound).

Create GitHub environment cloudflare-v4-staging and a dedicated Cloudflare account token scoped only to the staging account, with Workers and D1 permissions; create an empty database named nexoraid-v4-staging. Store token as environment secret STAGING_CLOUDFLARE_API_TOKEN. Set environment variables STAGING_ACCOUNT_ID, STAGING_D1_DATABASE_ID, STAGING_PUBLIC_ORIGIN (https://nexoraid-v4-staging.<subdomain>.workers.dev), PRODUCTION_ACCOUNT_ID, PRODUCTION_D1_DATABASE_ID as independent comparison values. Run Dedicated Cloudflare staging manually on main. It checks target inventory before mutation and rejects equal account or database IDs. No automated production promotion and no real Discord credentials. Cloud deployment remains unverified until this workflow runs successfully.
